## Shared data / API (strings deliberately avoid macro include coupling)

- `/proc/get_tactical_plan(faction)` returns round-local `/datum/tactical_plan`; keyed by faction in `GLOB.tactical_plans`.
- `/proc/can_use_tactical_command(mob/user)` human, conscious, client, leadership >= SKILL_LEAD_TRAINED (or admin holder), respects existing command role bans. UI should revalidate every ui_act.
- `/datum/tactical_plan`: `faction`, `list/zones`, `list/routes`, `list/squads` (ordinary ordered lists, objects have stable string `id`), `revision`. `find_zone(id)`, `find_route(id)`, `find_squad(id)`. `next_id(prefix)`. `touch()` increments revision.
- Plan `create_zone(name, list/turfs, purpose="guard")` returns zone or null with invalid/oversize/mixed-Z geometry; max 1600 tiles, 32 zones. `create_rectangle(name,turf/a,turf/b,purpose)` convenience. `create_room(name,turf/at,purpose)` uses exact area object on same Z. `delete_zone(zone)` rejects if referenced by any squad guard/fallback; returns bool. `create_route(name,list/waypoints,loop=TRUE)` max 32 points, same Z, 32 routes; `delete_route(route)` rejects active refs. Plan `remove_squad(squad)` owned by parent will qdel and remove list; UI handles create via `new /datum/tactical_squad(plan,name)` then adds to plan.squads only if constructor doesn't (AI worker confirm).
- `/datum/tactical_zone`: `id`, `name`, `purpose` (guard/fallback/staging), `z`, `list/turfs`, `list/markers`, bounds `min_x,max_x,min_y,max_y`, `turf/center`. `contains(atom)`, `nearest_turf(atom)`, `set_purpose(purpose)`, `add_marker(kind,turf,dir=NORTH)` returns marker or null (entrance/choke, up to16; same Z, in/adjacent to zone). `remove_marker(id)`. Reclassification never changes geometry or engine area. `/datum/tactical_marker`: id, kind, turf/position, direction.
- `/datum/tactical_route`: id,name,z,list/waypoints,loop. Geometry is ordered, no omniscient contacts.
- `/datum/tactical_squad` (AI worker): id,name,plan,faction,list/members (human mobs), order (hold/follow/guard/patrol/retreat), zone, route, fallback_zone, follow_target, hold_position, waypoint_index, status. `add_member(human)` only same-faction existing AI (no client) and not another squad unless explicit transfer; `remove_member(human)`; `issue_order(order, zone=null, route=null, mob/follow_target=null, turf/position=null)` bool; `set_fallback(zone)` bool; `get_member_status(human)` string. Constructor should register in plan.squads and Destroy unregister/detach.
- Human AI gets `datum/tactical_squad/tactical_squad`; UI can inspect component.ai_behavior to show membership, only human AI recruited. Managed AI bypasses old greedy movement/task policy but reuses weapons/navigation/actions. Clear membership on deletion; player takeover must never be moved. Plain old NPCs stay legacy until recruited.
- Squad follow/guard/patrol/retreat remain persistent despite temporary combat. Guard never chases outside zone; follow returns to leader without chasing bait; hold keeps formation near chosen point. Manual retreat uses per-squad fallback and stays until explicitly reassigned. Routes progress in order, squad cohesion before advancing, loop or reverse. Member statuses explain blocked/rejoining/fighting/holding.

## UI

Accessible command view (new action alongside existing leader designator, optional item for admin spawn), no requirement for unseen NPCs to be clicked again. Named squad list with roster, local recruitment and explicit transfer/release. Deselect UI is not cancel orders. Saved zone list, room/rectangle drawing on tactical map with preview, save and reclassify/rename/delete validation. Route waypoint editing/preview, entrance/choke markers with selected zone, assignments and per-squad fallback. Map only static terrain plus friendly NPC/player marks, no enemies. Cap/validate coordinates and work server-side; ownership/faction must not be trusted from browser. No arbitrary ref locate without membership validation. Use current Z; don't expose every level.

A new admin-spawnable `/obj/item/tactical_command_tablet` may grant interface only to suitable command users; existing leader action should be main entry. Preserve construction designator functionality. Test guide covers acquiring/spawning squads, opening UI, drawing, assignments and limitations.
